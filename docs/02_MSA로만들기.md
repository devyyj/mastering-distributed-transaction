# MSA 전환 가이드: 모놀리스에서 MSA로

본 문서는 `monolith` 프로젝트를 마이크로서비스 아키텍처(MSA)로 전환하기 위한 가이드라인과 설계 원칙을 정의합니다.

## 1. 전환 목표 및 원칙

- **서비스 독립성**: 각 도메인을 독립적인 프로젝트(`my-*`)로 분리하여 독자적인 생명주기를 갖도록 합니다.
- **Shared-Nothing (비공유 원칙)**: 서비스 간 코드 공유를 배제하며, 각 프로젝트는 독립적으로 빌드 및 배포될 수 있는 환경을 구축합니다.
- **API 기반 통신**: 서비스 간의 모든 상호작용은 정의된 REST API를 통해서만 이루어집니다.
- **데이터베이스 분리 (Database-per-Service)**: 각 서비스는 자신만의 전용 데이터베이스를 소유하며, 다른 서비스의 데이터베이스에 직접 접근하는 것을 금지합니다.

## 2. 서비스 구조 및 통신 흐름

### 2.1 분리 대상 서비스
- **my-order**: 주문 도메인 관리 (기존 `order` 패키지 마이그레이션)
- **my-payment**: 결제 도메인 관리 (기존 `payment` 패키지 마이그레이션)
- **my-point**: 포인트 도메인 관리 (기존 `point` 패키지 마이그레이션)

### 2.2 서비스 통신 흐름
주문 프로세스는 다음과 같은 동기식 REST 호출 흐름으로 진행됩니다.
1. **my-order**: 사용자로부터 주문 요청을 수신하고 주문 정보를 생성합니다. (상태: `PENDING`)
2. **my-order → my-point**: 포인트 사용 처리를 위한 REST API를 호출합니다.
3. **my-order → my-payment**: 포인트 처리 완료 후 결제 승인을 위한 REST API를 호출합니다.

## 3. 인프라 및 데이터 저장소 설정

- **독립 데이터베이스**: 각 서비스 프로젝트 루트에 `docker-compose.yml` 파일을 작성하여 MariaDB 컨테이너를 구성합니다.
- **포트 할당 전략**: 로컬 환경에서의 중복을 피하기 위해 서비스별로 고유한 포트를 할당합니다.
  - `my-order`: 8081
  - `my-point`: 8082
  - `my-payment`: 8083

## 4. 테스트 및 검증 전략

- **통합 API 테스트**: 프로젝트 최상위 루트 디렉토리에 `msa-test.http` 파일을 생성하여 전체 서비스 간 워크플로우를 검증합니다.
- **서비스별 단위 검증**: 각 프로젝트 내에서 TDD 방식으로 비즈니스 로직과 API 엔드포인트를 독립적으로 검증합니다.

## 5. 단계별 실행 체크리스트

- [ ] `my-order`, `my-payment`, `my-point` 개별 프로젝트 환경 구성
- [ ] 서비스별 `docker-compose.yml` 설정 및 데이터베이스 연결 확인
- [ ] 도메인별 핵심 로직(Entity, Service, Repository, Controller) 마이그레이션
- [ ] 서비스 간 통신을 위한 HTTP 클라이언트(예: RestTemplate, OpenFeign) 구현
- [ ] 서비스 분리에 따른 분산 환경 예외 처리 로직 고도화
- [ ] `msa-test.http`를 통한 전체 시나리오 통합 테스트 수행 및 검증
