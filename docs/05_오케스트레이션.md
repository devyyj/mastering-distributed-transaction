# 05. Temporal을 활용한 오케스트레이션 Saga 패턴 적용 계획

## 1. 개요
본 문서는 Temporal 기반의 오케스트레이션 Saga 패턴을 도입하여 분산 트랜잭션을 관리하는 아키텍처 및 구현 계획을 설명합니다. 기존 코레오그래피 방식이나 단순 보상 트랜잭션에서 발생하는 복잡성과 가시성 부족 문제를 Temporal Workflow를 통해 해결합니다.

## 2. 목적
- 분산된 서비스 간의 복잡한 트랜잭션 흐름을 중앙 집중적으로 관리 (Orchestrator 역할)
- 실패 시 자동 재시도 및 보상 트랜잭션(Compensation)의 신뢰성 있는 실행 보장
- 비즈니스 로직과 트랜잭션 관리(오케스트레이션) 로직의 명확한 분리

## 3. 아키텍처 구조 (Layered Architecture 준수)
Temporal을 활용할 때 주요 구성 요소는 Workflow와 Activity로 나뉩니다.
- **Workflow (Orchestrator):** 트랜잭션의 전체 흐름(Saga)을 제어합니다. 상태를 유지하며 각 단계의 성공 여부에 따라 다음 단계나 보상 흐름을 결정합니다.
- **Activity (Local Transaction):** 각 도메인 영역(주문, 결제, 재고 등)에서 실제 비즈니스 로직을 수행합니다. Activity 내부에서 기존 서비스 레이어 로직을 호출하게 됩니다.

## 4. Saga 패턴 흐름도 예시 (주문 생성 시나리오)
1. `OrderWorkflow` 시작
2. **Activity 1:** `CreatePendingOrder` (주문 대기 상태 생성)
3. **Activity 2:** `ReserveInventory` (재고 확보)
   - *실패 시:* `CancelOrder` (주문 취소 보상 트랜잭션) 후 Workflow 예외 종료
4. **Activity 3:** `ProcessPayment` (결제 처리)
   - *실패 시:* `RestoreInventory` (재고 복구 보상 트랜잭션), `CancelOrder` (주문 취소 보상 트랜잭션) 순차적 실행 후 Workflow 예외 종료
5. **Activity 4:** `CompleteOrder` (주문 완료 상태 변경)
6. Workflow 정상 종료

## 5. 단계별 구현 계획

### Step 1: Temporal 인프라 및 환경 설정
- [ ] Temporal 서버 구성 (Docker Compose 활용 로컬 환경 구축)
- [ ] 프로젝트에 Temporal Java SDK 의존성 추가
- [ ] Temporal Client 및 Worker 설정 (Spring Bean 등록)

### Step 2: 도메인별 Activity 정의 및 구현 (TDD 적용)
- 서비스 레이어와 연동되는 Activity 구현
- [ ] 주문(Order) Activity 인터페이스 및 구현체 작성 (주문 생성, 취소)
- [ ] 재고(Inventory) Activity 인터페이스 및 구현체 작성 (재고 확보, 복구)
- [ ] 결제(Payment) Activity 인터페이스 및 구현체 작성 (결제 승인, 취소)
- *주의:* 모든 기능은 TDD 방식을 기반으로 테스트 코드를 선행 작성 후 구현합니다.

### Step 3: Saga Workflow 구현
- [ ] `OrderWorkflow` 인터페이스 및 구현체 작성
- [ ] Temporal Java SDK의 `Saga` 클래스를 활용하여 성공적인 Activity 실행 후 보상(Compensation) 로직 등록
- [ ] 오류 발생 시 `Saga.compensate()`를 호출하여 등록된 보상 트랜잭션 역순 실행

### Step 4: 컨트롤러(API) 연동
- [ ] 클라이언트의 요청(Request DTO)을 받아 Workflow Client를 통해 Workflow 시작
- [ ] 상위 레이어에서 하위 레이어로 데이터를 전달할 때 DTO 변환 규칙 준수 (Controller DTO -> Service/Command DTO)

### Step 5: 통합 테스트 및 검증
- [ ] `TestWorkflowEnvironment`를 활용한 Workflow 단위/통합 테스트 작성
- [ ] 정상 결제 흐름 검증
- [ ] 재고 부족 시 보상 트랜잭션(주문 취소) 작동 검증
- [ ] 결제 실패 시 보상 트랜잭션(재고 복구 -> 주문 취소) 작동 검증

## 6. 기대 효과
- **가시성 확보:** Temporal Web UI를 통해 각 트랜잭션의 현재 상태, 진행 단계 및 실패 원인을 한눈에 파악할 수 있습니다.
- **장애 내결함성:** 서버 크래시나 네트워크 오류 발생 시에도 Temporal 서버가 상태를 유지하여 복구 후 중단된 지점부터 안전하게 재개 가능합니다.
- **코드 유지보수성 향상:** 분산 트랜잭션 흐름이 코드로 명확히 기술되어 디버깅 및 비즈니스 흐름 파악이 용이해집니다.
