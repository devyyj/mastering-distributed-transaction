# 보상 트랜잭션 기능 추가 및 코드 개선

## 1. 보상 트랜잭션 (Saga Pattern) 기능 추가

분산 환경에서의 데이터 일관성을 위해 Saga 패턴 기반의 보상 트랜잭션 로직을 추가합니다.

### my-order 서비스
- **보상 트랜잭션 흐름 제어**: `my-order` 서비스에서 `my-payment` 서비스 호출 시 실패(예외)를 응답받으면, 이미 성공한 `my-point` 서비스의 작업을 취소하기 위해 포인트 복구 API를 호출합니다.
- **예외 처리**: 외부 서비스 호출 중 발생하는 예외를 catch하여 적절한 보상 로직을 실행해야 합니다.

### my-point 서비스
- **포인트 복구 로직**: 포인트 복구를 위한 `restorePoint` 메서드를 서비스 레이어에 추가합니다.
- **복구 API 제공**: `my-order` 서비스가 보상 트랜잭션을 실행할 수 있도록 컨트롤러에 REST API 엔드포인트(예: `POST /api/points/restore`)를 추가합니다.

## 2. 코드 개선 및 기술적 요구사항

### 2.1 트랜잭션 상태 유지 및 커밋 (Persistence of Failure State)
각 마이크로서비스는 장애 상황에서도 비즈니스 추적 가능성을 위해 실패 상태를 데이터베이스에 기록하고 커밋해야 합니다.

- **my-order 서비스**: 
  - 포인트 차감 또는 결제 요청 중 예외가 발생하면 주문(`Order`) 상태를 `FAIL`로 업데이트하고 커밋합니다.
  - Spring의 `@Transactional`은 기본적으로 RuntimeException 발생 시 롤백하므로, 예외를 catch하여 상태를 변경하고 정상 종료하거나, `@Transactional(noRollbackFor=...)` 설정을 고려해야 합니다.
- **my-payment 서비스**: 
  - 결제 한도 초과 등 비즈니스 예외 발생 시, 예외를 반환하기 전에 결제(`Payment`) 상태를 `FAIL`로 저장하고 커밋합니다.
  - 상태 저장 로직은 별도의 트랜잭션(`Propagation.REQUIRES_NEW`)으로 분리하여, 전체 로직이 롤백되더라도 실패 기록은 남도록 구성합니다.

### 2.2 상세 로깅 및 에러 메시지
시스템 운영 및 디버깅을 위해 명확한 로그와 응답 메시지를 제공합니다.

- **응답 메시지**: `ApiResponse`의 `message` 필드에 "결제 한도 초과", "포인트 잔액 부족" 등 구체적인 실패 원인을 담아 반환합니다.
- **로깅 전략 (SLF4J)**:
  - **INFO**: 비즈니스 흐름의 주요 체크포인트 (주문 생성 시작, 포인트 차감 완료, 결제 시도, 보상 트랜잭션 시작 등)
  - **ERROR**: 예외 발생 상황 및 보상 트랜잭션 실패 시점 (구체적인 에러 메시지와 스택 트레이스 포함)

## 3. 테스트 및 검증
- `my-payment` 서비스에서 인위적으로 실패를 유발하여 `my-point`에서 포인트가 정상적으로 복구되는지 확인합니다.
- 실패 상황에서도 `my-order`와 `my-payment`의 데이터베이스에 각각 `FAIL` 상태의 레코드가 생성되는지 확인합니다.
